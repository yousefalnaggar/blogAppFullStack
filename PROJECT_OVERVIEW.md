## Backend Flow (Request to Database)

```
Browser / React
     │
     │  HTTP Request (GET, POST, PUT, DELETE)
     ▼
BlogPostsController.cs
     │  Receives the request, validates input via DTOs
     │
     ▼
BlogDbContext.cs  (Entity Framework Core)
     │  Translates C# code into SQL queries automatically
     │
     ▼
SQL Server (BlogAppDb database)
     │  Executes the SQL and returns results
     │
     ▼
BlogDbContext.cs → Controller → HTTP Response (JSON)
     │
     ▼
React frontend (renders the data)
```

### Step-by-step example — Creating a post

1. React sends `POST /api/blogposts` with `{ title, content, author }` as JSON
2. `BlogPostsController` receives it, maps it to a `BlogPost` model object
3. `db.BlogPosts.Add(post)` + `db.SaveChangesAsync()` — EF Core generates:
   ```sql
   INSERT INTO BlogPosts (Title, Content, Author, CreatedAt, UpdatedAt)
   VALUES ('My Title', 'Hello...', 'Joe', ..., ...)
   ```
4. SQL Server stores the row and returns the new `Id`
5. The controller returns `201 Created` with the saved post as JSON
6. React adds the new post to the list

## Key Files Explained

### `Models/BlogPost.cs`
Defines the shape of a blog post. Each property maps to a column in the database table.

```
BlogPost
├── Id          → int          (Primary Key, auto-incremented)
├── Title       → nvarchar(max)
├── Content     → nvarchar(max)
├── Author      → nvarchar(max)
├── CreatedAt   → datetime2
└── UpdatedAt   → datetime2
```

### `Data/BlogDbContext.cs`
The "bridge" between C# and SQL Server. Entity Framework Core uses this to:
- Know which tables exist (`DbSet<BlogPost>`)
- Generate and run SQL queries from C# code
- Track changes to objects and sync them to the database

### `DTOs/BlogPostDtos.cs`
DTOs (Data Transfer Objects) control what data comes in and goes out of the API:
- `CreateBlogPostRequest` — what the client must send to create a post
- `UpdateBlogPostRequest` — what the client must send to update a post
- `BlogPostResponse` — what the API sends back (never exposes raw model directly)

### `Migrations/`
Auto-generated by EF Core when you run `dotnet ef migrations add`. These files describe how to create/alter the database schema. Running `dotnet ef database update` (or starting the app) applies them to SQL Server.

### `Program.cs`
The app startup. In order it:
1. Registers `BlogDbContext` with the SQL Server connection string
2. Configures CORS so React (port 5173) can call the API (port 5000)
3. On startup, automatically applies any pending migrations
4. Maps controllers to routes

### `appsettings.json`
Holds the database connection string:
```
Server=localhost → connects to your local SQL Server (MSSQLSERVER instance)
Database=BlogAppDb → the database name (created automatically)
Trusted_Connection=True → uses Windows Authentication (no username/password needed)
```

## API Endpoints

| Method | URL | What it does |
|--------|-----|--------------|
| GET | `/api/blogposts` | Get all posts (newest first) |
| GET | `/api/blogposts/{id}` | Get one post by ID |
| POST | `/api/blogposts` | Create a new post |
| PUT | `/api/blogposts/{id}` | Update an existing post |
| DELETE | `/api/blogposts/{id}` | Delete a post |

## Where to View the Database

Your database lives on your local SQL Server instance (`MSSQLSERVER`). You can browse it with any of these tools:

### Option 1 — SQL Server Management Studio (SSMS) ✅ Recommended
The official free GUI tool from Microsoft.

1. Open **SSMS**
2. In the connect dialog:
   - **Server name:** `localhost` (or `.`)
   - **Authentication:** Windows Authentication
3. Click **Connect**
4. In the Object Explorer on the left expand:
   ```
   localhost
   └── Databases
       └── BlogAppDb
           └── Tables
               └── dbo.BlogPosts   ← your data is here
   ```
5. Right-click `dbo.BlogPosts` → **Select Top 1000 Rows** to see all posts

### Option 2 — Azure Data Studio
A lighter, cross-platform alternative to SSMS. Connect the same way (`localhost`, Windows Auth).

### Option 3 — VS Code Extension
Install the **SQL Server (mssql)** extension, then connect to `localhost` with Windows Authentication. You can run queries directly in VS Code.

### Quick query to see all posts
Once connected, open a new query window on `BlogAppDb` and run:
```sql
SELECT * FROM BlogPosts ORDER BY CreatedAt DESC;
```

## How to Run the App

**Terminal 1 — API:**
```bash
cd BlogApp\BlogApp.API
dotnet run
# API running at http://localhost:5000
```

**Terminal 2 — React:**
```bash
cd BlogApp\blog-client
npm run dev
# Frontend at http://localhost:5173
```
